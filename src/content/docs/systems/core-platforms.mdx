## Core system categories

Before the vendor names, the categories. Insurance IT organises around a recognisable set of
systems, and most vendor comparisons are really comparisons within one of these boxes.

<Ledger>
  <LedgerRow term="PAS">
    Policy Administration System — product configuration, quoting, rating, underwriting
    workflow, issuance, endorsements, renewals. "Core transformation" usually means replacing a
    legacy PAS.
  </LedgerRow>
  <LedgerRow term="Claims system">
    FNOL through settlement: reserves, payments, recoveries, litigation tracking.
  </LedgerRow>
  <LedgerRow term="Billing">
    Invoicing, installments, commissions, dunning — complex enough to ship as its own module.
  </LedgerRow>
  <LedgerRow term="Rating engine">
    Sometimes embedded, sometimes standalone so actuaries can change rates without a code release.
  </LedgerRow>
  <LedgerRow term="Underwriting workbench">
    Commercial submission triage, data enrichment, exposure analysis.
  </LedgerRow>
  <LedgerRow term="Agency systems">
    The broker and agent side of the integration surface.
  </LedgerRow>
  <LedgerRow term="Document / CCM">
    Policy documents and correspondence generation.
  </LedgerRow>
  <LedgerRow term="Reinsurance admin">
    Treaty and facultative administration, cessions and recoveries.
  </LedgerRow>
  <LedgerRow term="Fraud & analytics">
    Fraud detection, plus the data warehouse and regulatory reporting stack every insurer runs.
  </LedgerRow>
</Ledger>

<SystemsNote>
The content plan says to compare these **on model, not marketing**, and the table above does not
yet do that — it is an orientation list.

The axis that actually distinguishes these platforms is **how much of the domain model is
configuration versus code**: whether a new coverage is a config change or a release, whether
rate tables are actuary-editable artefacts or developer-owned, and whether effective dating is
a first-class primitive or something each implementation rebuilds.

Feature-list comparisons will not tell you this. Reading each vendor's product model will.
</SystemsNote>
