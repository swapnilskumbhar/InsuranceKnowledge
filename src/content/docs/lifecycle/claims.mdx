## Reserves are an event stream

A reserve is not the claim's current estimated cost. It is **the history of every estimate ever
made**, each with the date it was set and the reason it changed.

Finance needs the movement between two dates, not the latest figure. Actuaries need the
development pattern — how estimates on claims of this type evolve from first notice to close —
because that pattern is what produces next year's IBNR. A schema storing `reserve_amount` as a
mutable column destroys both, and the loss is not recoverable after the fact.
